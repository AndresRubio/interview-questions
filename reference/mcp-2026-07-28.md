# MCP 2026-07-28 — the breaking revision

A one-page diff against `2025-11-25`. Everything here is `verified 3-0`.

> Compiled 10 September 2026, when this revision was ~6 weeks old. SDK, server and client migration was actively in flux (`typescript-sdk` issue #2185 tracked implementation). Expect third-party tutorials to still describe the old semantics.

## The four things that broke

| Change | SEP | Consequence |
|---|---|---|
| `initialize` / `notifications/initialized` handshake **removed** | 2575 | Version + capabilities travel per-request in `_meta` |
| Protocol sessions and `Mcp-Session-Id` **removed** | 2567 | Cross-call state uses server-minted handles as tool arguments |
| SSE resumability **removed** | — | Broken stream MUST be re-issued as a new request, new request ID |
| Server-initiated requests **removed** | 2322 | Replaced by Multi Round-Trip Requests (MRTR) |

## New per-request `_meta` keys

```
io.modelcontextprotocol/protocolVersion
io.modelcontextprotocol/clientCapabilities
io.modelcontextprotocol/logLevel
```

Plus a mandatory `server/discover` RPC advertising supported versions, capabilities and identity. Mismatch raises `UnsupportedProtocolVersionError`.

**Mechanically verifiable:** the 2026-07-28 `schema.json` (181,474 bytes) contains **zero** occurrences of `initialize`. The method is absent, not deprecated.

## MRTR in one exchange

```
client → server   original request (id: 1)
server → client   InputRequiredResult
                    resultType: "input_required"
                    inputRequests: { <server-assigned id>: ... }
client → server   retry (id: 2)   ← MUST differ from id 1
                    inputResponses: { <matching id>: ... }
server → client   resultType: "complete"
```

All results now carry a required `resultType` of `complete` or `input_required`. Clients MUST treat a **missing** `resultType` from an older server as `complete`.

`inputRequests` is itself optional in the schema — handle its absence.

## Deprecation lifecycle

New **Active / Deprecated / Removed** states, minimum **twelve-month** window, public registry (SEP-2596).

| Feature | Status | Earliest removal | Migrate to |
|---|---|---|---|
| Roots | Deprecated (SEP-2577) | first revision on/after **2027-07-28** | Tool parameters, resource URIs, server config |
| Sampling | Deprecated (SEP-2577) | first revision on/after **2027-07-28** | Direct LLM provider APIs |
| Logging | Deprecated (SEP-2577) | first revision on/after **2027-07-28** | stderr or OpenTelemetry |
| HTTP+SSE | Deprecated | **3 months after SEP-2596 reaches Final** | Streamable HTTP |

Note the asymmetry: HTTP+SSE does **not** get the twelve-month clock.

**Removed outright:** `logging/setLevel`, `notifications/roots/list_changed`.

As of compilation, the registry stated no features had yet been removed under this policy.

## Security rules worth memorising

**Token passthrough — forbidden.**
- MUST validate tokens were issued specifically for this server as intended audience, per **RFC 8707 §2**
- MUST NOT accept **or transit** any other tokens

**Confused deputy — four conditions, all required:**
1. Static third-party client ID
2. Dynamic client registration for MCP clients
3. Third-party consent cookie set after first authorization
4. No per-client consent at the proxy

**Required protections:**
- Per-user registry of approved `client_id` values, checked **before** forwarding to the third-party auth server
- `redirect_uri` validated by **exact string match** — no wildcards, no patterns
- `state` single-use, short expiry (e.g. 10 min)
- No consent cookie until the user approves the proxy's own consent screen
